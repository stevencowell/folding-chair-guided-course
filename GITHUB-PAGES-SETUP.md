# GitHub Pages handover

## Recommended setup

Host this as a GitHub Pages site and link to it from Google Classroom. This preserves the course as a normal website, including the activities and the student PDF download.

Google Classroom should be used to give students the link and collect any final PDFs or teacher-directed submissions. It is not the right place to host the working website itself.

## Files to upload

Upload every item inside this folder:

```text
assets/
resources/
scripts/
styles/
weeks1-2/ through weeks19-20/
index.html
Folding-Chair-Project-Plans.pdf
README.md
TEACHER-NOTES.txt
```

Do not upload the outer Downloads folder as an extra wrapper. The file `index.html` must sit at the top level of the GitHub repository.

## Publish steps

1. Sign in to GitHub and create a new repository. It can be private while it is being reviewed.
2. Add the files listed above to the repository root and commit them to the `main` branch.
3. Go to **Settings → Pages**.
4. Select **Deploy from a branch**.
5. Select `main` and `/(root)`, then save.
6. GitHub will show the Pages address once it has deployed.
7. Open that address in a normal browser and test:
   - Home page and all four stage cards
   - Weeks 1–2, 3–4 and 5–6
   - Project-plan links
   - A knowledge check
   - A written response and its model response
   - First name, last name and class fields
   - Download PDF
8. Add the final Pages link to Google Classroom.

## Teacher notes

- GitHub Pages is static hosting. It cannot centrally collect or mark student answers.
- Each student’s answers remain in their browser until they choose **Download PDF**.
- If students use shared computers, they should download their PDF and use the reset button before another student uses the same browser profile.
- Publishing a Pages site makes the site accessible to anyone with the URL when the repository is public. Do not add student work, names or private school documents to the repository.
